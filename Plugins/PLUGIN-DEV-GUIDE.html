Minecraft Chat Overlay · 插件开发文档

给插件作者，也给 AI 看：这里写的是宿主真正认的规矩，不是设想。

apiVersion = 1 TargetFramework = net8.0-windows 契约程序集不引 WPF 插件 = dll + plugin.json + zip

0. 一句话总览

插件是一个独立编译的 C# 类库：你的插件.dll + plugin.json，压成一个 zip 发给别人， 用户在软件里「插件」页拖进去就装好了。装好后它不会另占一个导航卡片，而是出现在「插件」板块里的一张卡片上， 点「进入」才进它自己的页面。

插件只引用契约程序集 MinecraftChatOverlay.Plugin.Abstractions.dll， 永远不要引用主程序 exe —— 这样主程序内部怎么改都不会把你的插件弄碎。

宿主给插件的界面是两种：交数据（表单式，宿主画）或交控件（自绘，你画）。其余能力（收聊天、发悬浮窗、列窗口、写日志、弹提示、存配置） 都由 IPluginHost 提供。

1. 5 分钟写出第一个插件

1.1 建工程

新建类库，只引用契约程序集。不要引用主程序 exe。

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0-windows</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <LangVersion>latest</LangVersion>
    <!-- 只在需要自己画界面时才开；纯逻辑插件可以不写 -->
    <UseWPF>true</UseWPF>
    <AssemblyName>MyPlugin</AssemblyName>
    <EnableDefaultApplicationDefinition>false</EnableDefaultApplicationDefinition>
  </PropertyGroup>

  <ItemGroup>
    <!-- 路径按你的目录调整；也可以直接引编译好的 dll -->
    <ProjectReference Include="..\Abstractions\MinecraftChatOverlay.Plugin.Abstractions.csproj" />
  </ItemGroup>

  <ItemGroup>
    <!-- 让 plugin.json 跟着输出目录，打包时省事 -->
    <None Update="plugin.json" CopyToOutputDirectory="PreserveNewest" />
  </ItemGroup>
</Project>
两个必须：入口类要 public、非抽象、有公开无参构造函数； 插件一个插件只能注册一个页面（重复调用以最后一次为准）。

1.2 写入口（完整可跑）

using MinecraftChatOverlay.Plugin;

namespace My.First.Plugin;

public sealed class MyPlugin : IPlugin
{
    private IPluginHost _host = null!;
    private MySettings _settings = new();
    private int _chatCount;
    private PluginField _toggle = null!;
    private PluginField _note = null!;

    public string Id => "you.myplugin";              // 稳定唯一，决定安装目录名，别随便改
    public string DisplayName => "我的插件";

    public void Initialize(IPluginHost host)
    {
        _host = host;

        // 1) 读自己的配置（文件在 %AppData%\MinecraftChatOverlay\plugin-data\you.myplugin\ 里）
        _settings = PluginSettingsFile.Load<MySettings>(host.PluginDirectory);

        // 2) 收聊天消息（事件在宿主 UI 线程触发，别做耗时操作）
        host.ChatLineReceived += OnChatLine;

        // 3) 注册页面：表单式 —— 你交数据，宿主画
        var page = new PluginPage
        {
            Title = DisplayName,
            Description = "演示插件：数一共收到多少条聊天，并往悬浮窗发消息。",
            StatusText = () => $"已收到 {_chatCount} 条聊天",
        };

        _note = new PluginField
        {
            Key = "note", Label = "说明", Kind = PluginFieldKind.ReadOnly,
            Text = "下面的开关改了会立刻存进插件自己的 settings.json。",
        };

        _toggle = new PluginField
        {
            Key = "echo", Label = "把聊天消息转发到悬浮窗", Kind = PluginFieldKind.Toggle,
            Bool = _settings.EchoToOverlay,
            Hint = "勾上之后，游戏里每收到一条聊天就往悬浮窗再发一条。",
            Changed = f => { _settings.EchoToOverlay = f.Bool; Save(); },
        };

        page.Fields.Add(_note);
        page.Fields.Add(_toggle);
        page.Actions.Add(new PluginAction
        {
            Label = "发一条测试消息", Primary = true,
            Invoke = () => { host.SendToOverlay("你好，我是插件"); return "已发送"; },
        });

        host.RegisterPage(page);
        host.Log($"[我的插件] 已加载，数据目录：{host.PluginDirectory}");
    }

    public void Shutdown()
    {
        // 退订事件、关自己的窗口/定时器
        _host.ChatLineReceived -= OnChatLine;
    }

    private void OnChatLine(ChatLine line)
    {
        _chatCount++;
        if (_settings.EchoToOverlay)
        {
            _host.SendToOverlay("[我的插件] " + line.Raw);
        }
    }

    private void Save() => PluginSettingsFile.Save(_host.PluginDirectory, _settings);

    /// <summary>插件自己的配置（JSON 字段名就是属性名）</summary>
    private sealed class MySettings
    {
        public bool EchoToOverlay { get; set; }
    }
}

1.4 编译 + 打包

本仓库自带一键脚本，会编译契约 + 所有插件、装到本机、并打出可分发的 zip：

build-plugins.bat

产物：%AppData%\MinecraftChatOverlay\plugin-packages\<你的 id>.zip。 手动打包就是：把 你的插件.dll + plugin.json 一起压成 zip（zip 里可以是根目录平铺，也可以套一层文件夹，两种宿主都认）。

1.5 安装与验证

  1. 打开软件 → 左侧「插件」页 → 把 zip 拖到这一页（或点「导入插件包（zip）」）
  2. 宿主会弹确认框，列出你 plugin.json 里写的 capabilities —— 用户点确定才装
  3. 装好后「已装的插件」里出现你的卡片：标题 / 作者 / 版本 / 用途，点「进入」就是你的页面
  4. 卡上还有「禁用 / 卸载 / 打开目录」；插件的数据在 plugin-data\<id>\

2. 工程与目录约定

项目要求
目标框架net8.0-windows（必须与宿主一致，否则装载时会报框架不匹配）
引用只引 MinecraftChatOverlay.Plugin.Abstractions；永远不要引主程序 exe
需要界面自己的 csproj 开 <UseWPF>true</UseWPF>
需要模拟按键 / SendKeys再开 <UseWindowsForms>true</UseWindowsForms>，此时 Clipboard、UserControl 会二义，写全名
文件编码.cs / .json / .xaml 一律 UTF-8 无 BOM、CRLF（与仓库其它文件一致）
zip 里放什么你的插件.dll + plugin.json（可选：资源文件、附属 dll）。不要把 bin/obj、其它插件的 dll 打进去

宿主侧的目录（插件运行时能看到什么）

路径含义
<程序目录>\plugins\<id>\便携/内置插件根（跟着 exe 走，开发时用）
%AppData%\MinecraftChatOverlay\plugins\<id>\用户导入安装的插件根（发布给用户走这里）
%AppData%\MinecraftChatOverlay\plugin-data\<id>\插件数据目录（host.PluginDirectory）。配置/图片/缓存放这里；更新插件不会动它，卸载时整目录删掉
%AppData%\MinecraftChatOverlay\plugin-packages\build-plugins.bat 打出的 zip（方便试装/分发）
为什么数据目录要和安装目录分开：更新插件是「整目录替换」（删旧目录 → 落新文件）。 配置如果放在安装目录里，用户设置会被换版吃掉 —— 这是宿主刻意做的隔离。

3. 生命周期与宿主行为

3.1 装载流程（宿主真正做的顺序）

  1. 扫描两个插件根目录（exe 旁 plugins\ 与用户目录 plugins\），每个子目录当作一个插件
  2. 读 plugin.json；读不出来或缺 id → 跳过并记日志
  3. 校验 apiVersion：必须完全等于 PluginApi.Version，不等就拒装并在界面上说明原因
  4. 找到主 dll（assembly 指定，或目录里第一个非契约程序集的 dll）
  5. 为这个插件建一个可卸载的 AssemblyLoadContext，在里面加载 dll；契约程序集回落到宿主那一份（否则 IPlugin 类型身份不一致，cast 必失败）
  6. 找入口类型：entry 指定，或自动找唯一实现 IPlugin 的 public 非抽象类
  7. new 出来 → 调 Initialize(host)。这一步抛异常 → 卡片显示「装载失败 + 原因」，其它插件与主程序不受影响

3.2 隔离与容错

  • 每个插件独立 ALC：插件之间的类型互不可见（除非通过契约）；卸载时尽量回收
  • 宿主在每一次「宿主 → 插件」调用外面都包了 try/catch：Initialize、Shutdown、 StatusText、字段 OptionsProvider、Changed、按钮 Invoke、 ChatLineReceived 的每个订阅者。插件抛异常 → 只影响那一条操作，界面会显示原因
  • 插件跑在主程序进程里，权限和主程序一样：能用 HttpClient、P/Invoke、WPF 窗口、读写文件。 安装 zip = 执行任意代码，所以宿主要在安装时把 capabilities 摊给用户看

3.3 线程

回调线程注意
IPluginHost.ChatLineReceived宿主 UI 线程别阻塞（会卡住整个界面和聊天显示）。耗时的丢 Task.Run，回到 UI 用 Dispatcher.InvokeAsync
PluginField.Changed / PluginAction.Invoke宿主 UI 线程同上；Invoke 返回的字符串会当提示弹出来
PluginPage.StatusText宿主 UI 线程，约每秒一次只做取值+拼接，别在里面干活
PluginField.OptionsProvider宿主 UI 线程秒级刷新；取窗口列表这类"快"操作可以，联网请求请自己缓存

3.4 启用 / 禁用 / 卸载 / 更新

动作宿主行为
禁用当前进程里立即 Shutdown() + 卸载；id 记进禁用列表，下次启动不再装载（插件看不见任何"被禁用"的迹象，因为根本没加载）
启用立刻重新装载并 Initialize
卸载删插件安装目录 + plugin-data\<id>\。如果 dll 还被占用（插件正在运行），会禁用它并把目录排进"下次启动删"
更新（导入同 id 的新 zip）旧版没在跑 → 直接覆盖；旧版在跑（dll 被操作系统锁住）→ 新版本整包放到 <id>.new\，下次启动自动换上去，数据目录不动
给作者的建议：把「更新插件」当成常态设计 —— 用户数据（配置、下载的图片、缓存）一律写进 host.PluginDirectory， 不要写在安装目录里；这样用户更新你的插件时，设置和缓存都还在。

3.5 契约版本与兼容

  • PluginApi.Version 当前是 1；plugin.json 的 apiVersion 必须一致
  • 契约原则是只增不减：接口加成员、加字段没问题；删/改签名必须把 Version 加 1
  • 版本不匹配的表现是「明确告知 + 拒装」，不会出现"装上了但一调用就崩"

4. API 参考（契约全文）

命名空间 MinecraftChatOverlay.Plugin，全部在契约程序集里。 源码就是唯一事实来源：Plugins\Abstractions\PluginApi.cs。

4.1 PluginApi

成员说明
const int Version = 1契约版本。plugin.json 的 apiVersion 必须等于它

4.2 IPlugin —— 插件入口

成员类型说明
Idstring稳定唯一 id，形如 goldiamond.autogg。装插件、数据目录、禁用列表都用它，发布后不要改
DisplayNamestring插件卡片和页面标题上显示的名字
Initialize(IPluginHost host)void装载时调用一次。抛异常 → 被标成"装载失败"（不影响主程序）
Shutdown()void禁用 / 卸载 / 退出时调用。窗口、定时器、线程、事件订阅都要在这里收干净

4.4 数据记录

public sealed record ChatLine(string Raw, DateTime Time);
public sealed record GameWindowInfo(IntPtr Handle, int ProcessId, string ProcessName, string Title, int Width, int Height);
public sealed record PluginOption(string Key, string Text);
类型说明
ChatLine.Raw原始文本：已按日志编码解码、已去掉时间戳和日志前缀
ChatLine.Time宿主收到的时间（不是游戏里的时间戳）
GameWindowInfo.HandleHWND。要操作窗口时用它（ProcessId 给用户看已足够，但句柄才是可靠的）
GameWindowInfo.ToString()已经是给下拉框看的格式：进程名 窗口标题 (PID 1234) 1920×1080
PluginOption下拉项：Key 是插件自己定义的值（存配置用），Text 是界面显示

4.5 PluginPage —— 一个插件页面

成员类型说明
Titlestring（required）插件卡片标题 + 页面标题（必填）
Descriptionstring?标题下面那句说明；也用作插件卡片的「用途」
FieldsList<PluginField>表单式字段，按顺序画在同一张「设置」卡片里
ActionsList<PluginAction>按钮，画在「操作」卡片里

4.6 PluginField —— 表单字段

五种类型：Toggle（开关）、Slider（滑块）、Select（下拉框）、Text（单行输入）、ReadOnly（只读文本）。

属性类型适用说明
Keystring（required）全部插件内部用的键，随便起，自己认得就行
Labelstring全部界面上显示的名字
KindPluginFieldKind全部默认 Toggle
Hintstring?全部字段下面那行小字说明
Boolbool（可读写）Toggle开关状态
Numberdouble（可读写）Slider当前值
Minimum / Maximum / StepdoubleSlider下限（默认 0）/ 上限（默认 100）/ 步进（默认 1）
SuffixstringSlider数值后缀，例如 "×"、" fps"
NumberFormatstringSlider数值格式，默认 "0.#"（整数不显示小数点）
Textstring（可读写）Text / ReadOnly文本内容
SelectedKeystring?（可读写）Select当前选中项的 Key

{
    Key = "zoom", Label = "放大倍数", Kind = PluginFieldKind.Slider,
    Number = _settings.Zoom, Minimum = 1, Maximum = 8, Step = 0.5, Suffix = "×",
    Hint = "显示窗口大小 = 选区大小 × 倍数 ÷ 屏幕缩放。",
    Changed = f => { _settings.Zoom = f.Number; Save(); },
});

成员类型说明

Primarybooltrue = 主按钮（高亮）

4.8 PluginSettingsFile —— 存配置的工具

// 读：文件不存在或 JSON 坏了都返回一份默认值（不抛异常）
var settings = PluginSettingsFile.Load<MySettings>(host.PluginDirectory);

// 写：写失败不抛异常（配置丢了不该让插件崩）
PluginSettingsFile.Save(host.PluginDirectory, settings);

// 也可以换文件名（默认 settings.json）
PluginSettingsFile.Save(host.PluginDirectory, cache, "cache.json");
存的是 System.Text.Json 的默认序列化结果：属性名就是 JSON 字段名，中文会被写成 \uXXXX 转义（读取正常）。 文件落在 host.PluginDirectory。

5. 页面写法 A：表单式（推荐先试这个）

你只交数据，宿主用内置主题画。好处：外观永远和内置页一致，主程序换皮肤你也不用改。

宿主会画的来自
页头：标题 + 说明PluginPage.Title / Description
页头状态行（不给就不画）StatusText，宿主约每秒调一次
「设置」卡片Fields（按加入顺序）
「操作」卡片Actions（自动换行排列）

适合 / 不适合

适合
  • 开关、数值、下拉选择、文本输入
  • 选目标（进程/窗口/自己写的下拉）
  • 状态展示（ReadOnly 或 StatusText）
  • 几个动作按钮（框选、显示、重置……）
不适合
  • 可增删的规则列表、拖拽排序
  • 实时预览、画布、图表
  • 几十个控件的复杂面板

这些用第 6 节的自绘页面。

常用套路

// ① 下拉框选游戏窗口：每次渲染取一次 + 每 3 秒自动刷新
new PluginField
{
    Key = "target", Label = "游戏窗口", Kind = PluginFieldKind.Select,
    SelectedKey = _settings.TargetProcessName,
    OptionsRefreshSeconds = 3,
    OptionsProvider = () => host.GetGameWindows()
        .Select(w => new PluginOption(w.ProcessName, w.ToString()))   // ToString 已经是给人看的格式
        .ToList(),
    Hint = "游戏重启换了 PID 也没关系，按进程名重新找回来。",
    Changed = f => { _settings.TargetProcessName = f.SelectedKey ?? ""; Save(); },
}

// ② 只读文本当"结果展示"（宿主每秒刷新一次 Text）
new PluginField
{
    Key = "result", Label = "查询结果", Kind = PluginFieldKind.ReadOnly,
    Text = _lastResult,      // 你改这个字段，页面下一秒就会显示出来
}

// ③ 联动禁用：没选目标就禁用某些字段 / 按钮（宿主每秒按 Enabled 刷新）
_selectField.Enabled = !string.IsNullOrWhiteSpace(_settings.TargetProcessName);
_action.Enabled = _window is { IsVisible: true };

// ④ Changed 里存盘 + 立刻让效果生效（例如把新设置应用到自己的窗口）
Changed = f => { _settings.Zoom = f.Number; PluginSettingsFile.Save(host.PluginDirectory, _settings); _window?.ApplySettings(); }
状态行可以不要。如果你的页面已经用 ReadOnly 字段把状态讲清楚了，就别写 StatusText —— 宿主不会画那一行，页面更干净（自动 GG 插件就是这么做的）。

6. 页面写法 B：自绘页面

表单式表达不了时，给 ContentFactory 一个返回 WPF 控件的委托，这个控件会被当作页面的主体。

6.1 准确的调用时机（重要）

  • ContentFactory() 在插件装载/页面重建时调用一次，不是在每次点「进入」时调用；返回的控件会被保留复用 → 里面的状态请存在控件上（用户切走再切回来，控件还是同一个，状态不会丢）
  • 页头（标题 + 说明）仍然是宿主画的；StatusText 非空时状态行也照画
  • 设了 ContentFactory 后，Fields / Actions 不会再渲染（想混用就自己在控件里画）
  • 控件是在还没挂进窗口可视树的时候创建的 → 见下面第一条铁律
  • 控件抛异常 → 宿主拦住并把页面显示成出错信息，不会带走主程序
铁律 1：自绘页面里的样式 / 画刷一律用 DynamicResource，不能用 StaticResource。
插件控件先创建、后挂树，StaticResource 在解析那一刻沿自身→父级→Application 找资源， 而宿主的主题字典挂在 Window 上 → 直接抛 XamlParseException（整页白掉）。 DynamicResource 是延迟解析的，挂上树再找，没问题。
铁律 2：「控件值变化就存盘」的页面必须加加载闸门。
LoadFromSettings() 里第一个 IsChecked = true 会触发 Checked → SaveToSettings()， 此时后面的 TextBox 还是空的 → 把 ""/false 写回设置，用户的配置被清空。 写法：加一个 _loading 标志，填值期间让 SaveToSettings() 直接 return。

6.2 最小自绘页面

// AutoGgPage.xaml —— UserControl，内容就是原来的页面 XAML
<UserControl x:Class="My.First.Plugin.MyPage"
             xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml">
  <StackPanel>
    <Border Style="{DynamicResource CardStyle}">
      <StackPanel>
        <CheckBox x:Name="EnableCheckBox" Style="{DynamicResource ToggleSwitchStyle}">
          <StackPanel>
            <TextBlock Text="启用" FontSize="15" FontWeight="ExtraBold"/>
            <TextBlock Text="说明文字" FontSize="12" Foreground="{DynamicResource TextSecondaryBrush}"/>
          </StackPanel>
        </CheckBox>
      </StackPanel>
    </Border>
  </StackPanel>
</UserControl>
// 插件里注册
host.RegisterPage(new PluginPage
{
    Title = "我的插件",
    Description = "一句话说明。",
    ContentFactory = () => _page ??= new MyPage(this),   // 只建一次，复用
});

6.3 想长得像内置页面？用这些主题资源

资源名来自宿主的主题字典（ModernControls.xaml），在插件里用 {DynamicResource 名字} 引用即可：

类型可用名字
样式（Style）CardStyle、PanelTitleStyle、PanelDescStyle、 CardTitleStyle、CardDescStyle、FieldLabelStyle、HintStyle、 ToggleSwitchStyle、SmallButtonStyle、SmallPrimaryButtonStyle、SmallGhostButtonStyle
画刷（Brush）AccentBrush、AccentSoftBrush、SurfaceBrush、 Surface2Brush、BorderBrush、TextSecondaryBrush、MintBrush
转换器BoolToVis（bool → Visibility）
这些名字属于宿主的实现细节：主程序改主题时可能调整。 自绘页面用它们能立刻和内置页一致，但要接受"以后可能要跟着改"；表单式没有这个问题。
完整名单见 ModernControls.xaml 里的 x:Key（还有 PluginCardStyle、InlineToggleStyle、NavRadioButtonStyle、PrimaryButtonStyle、IconButtonStyle、DangerButtonStyle、SmallDangerButtonStyle、BareTextBoxStyle、TextPrimaryBrush、Surface3Brush、BorderStrongBrush 等）。

7. plugin.json 参考

放在 zip 根目录（和你的 dll 同级）。宿主解析时宽容：字段名大小写不敏感、允许 // 注释和尾逗号。

字段必需说明
id必需稳定唯一 id，形如 goldiamond.autogg。建议 作者前缀.插件名；决定安装目录名，也是禁用/更新/卸载的键。发布后不要改（改了等于换了个插件）
name强烈建议界面显示名（插件卡片标题、页面标题）
version强烈建议你自己的版本号，显示在卡片上（v1.0.0）
author建议作者，显示在卡片上
description建议一句话用途，显示成卡片的「用途：……」
apiVersion必需必须是 1（= PluginApi.Version）。对不上一律拒装
capabilities建议字符串数组，说明"这个插件会做什么"（读日志 / 联网 / 操作窗口 / 模拟按键……）。安装确认框会逐条列给用户看（知情同意）。它不是权限系统，不写也能用
entry可选入口类型全名。不写就自动找 dll 里唯一实现 IPlugin 的公开类（推荐不写）
assembly可选主 dll 文件名。不写就取目录里第一个非契约程序集的 dll（推荐不写）
{
  "id": "you.myplugin",
  "name": "我的插件",
  "version": "1.0.0",
  "author": "你的名字",
  "description": "一句话说明这个插件做什么。",
  "apiVersion": 1,
  "capabilities": [
    "读取聊天消息",
    "往悬浮窗发消息",
    "在自己目录里读写配置"
  ]
}

8. 打包、安装与分发

8.1 zip 里放什么

平铺（推荐） 
MyPlugin.zip
├─ MyPlugin.dll
├─ plugin.json
└─ （可选）Assets\...
套一层文件夹也行 
MyPlugin.zip
└─ MyPlugin\
   ├─ MyPlugin.dll
   └─ plugin.json
  • 不要把 bin/、obj/、*.pdb、其它插件的 dll 打进去
  • 如果你引用了第三方 NuGet 包，把需要的 dll 一起放进 zip（宿主会解析同目录的依赖）
  • 不要把契约程序集 MinecraftChatOverlay.Plugin.Abstractions.dll 放进 zip —— 宿主会强制用自己那一份（放进去也不会用，放错版本反而混淆）
  • 解压后宿主会删掉 :Zone.Identifier（从网上下载的 zip 会带这个"来自互联网"标记），不需要作者处理

8.2 用仓库自带脚本（省事）

build-plugins.bat
# 做的事：编译契约程序集 → 编译每个插件 → 装到 %AppData%\MinecraftChatOverlay\plugins\<id>\
#        → 打包成 %AppData%\MinecraftChatOverlay\plugin-packages\<id>.zip
跑脚本前先把软件关掉：正在运行的插件 dll 被系统锁着，覆盖会失败。

8.3 手动打包（用自己的工具链）

dotnet build MyPlugin.csproj -c Release
# 产物在 bin\Release\net8.0-windows\
# 把 MyPlugin.dll 和 plugin.json 压成 zip 即可

8.4 安装时用户看到什么

  1. 「插件」页 → 拖入 zip（或点「导入插件包（zip）」）
  2. 宿主读取 plugin.json 并校验：能不能解析、id 有没有、apiVersion 是否匹配、zip 里有没有越界路径
  3. 弹确认框：名字 v版本 · 作者 + description + 逐条列出 capabilities + 一句"插件权限和本程序一样，只装信任来源的"
  4. 确认后解压到 %AppData%\MinecraftChatOverlay\plugins\<id>\ 并立刻装载；「已装的插件」里出现卡片
  5. 装载失败时卡片显示原因（例如"装载失败：找不到实现 IPlugin 的公开类"）

8.5 更新与卸载（给作者的正确预期）

场景结果
用户在插件没运行时导入同 id 新版本直接覆盖安装目录，立刻生效
插件正在运行时导入新版本dll 被锁删不掉 → 新版本排进 <id>.new\ 队列，下次启动自动换上；数据目录不受影响
卸载安装目录 + 数据目录一起删；若文件被占用则排队到下次启动删
禁用立刻卸载（Shutdown() 会被调用），下次启动不再装载

9. 排错表（这些坑都真踩过）

现象原因改法
自绘页面整片白 / 抛 XamlParseException 用了 StaticResource 引宿主主题资源，而控件是先创建后挂树的 改成 {DynamicResource 名字}（见铁律 1）
用户的正则 / 文字设置被清空 填控件时触发了"值变即保存"，把还没填的空控件写回设置 加 _loading 闸门（见铁律 2）
编译报 CS0103: File / Path / Directory 不存在 UseWPF 的工程隐式 using 里没有 System.IO 相关文件加 using System.IO;
编译报 Clipboard / UserControl 二义 同时开了 UseWPF + UseWindowsForms，两套同名类型 写全名：System.Windows.Clipboard / System.Windows.Controls.UserControl
装载失败：找不到实现 IPlugin 的公开类 类不是 public / 是抽象类 / 没有公开无参构造 / 一个 dll 里有多个实现 按 4.2 的要求改；多个实现时用 plugin.json 的 entry 指定
拒装："版本对不上：这个插件要求契约版本 X" apiVersion 不等于宿主契约版本 改成 1（或按提示更新软件）
拒装："这个 zip 里没有 plugin.json" 打包时把 dll 单独压了，或压成了别的层级 确保 plugin.json 与主 dll 同目录（含套一层文件夹的情况）
拒装："zip 里有非法路径：../xxx" zip 里带了相对上级路径（宿主防目录穿越） 重新打包，不要包含 ..\ 条目
覆盖安装失败："文件还被占用" 软件没关，插件 dll 被系统锁住 关掉软件再装；或接受宿主把新版本排队到下次启动
插件装了但什么都不发生 开关没开（例如自动 GG 的「启用」）／事件没订阅／逻辑里提前 return 用 host.Log(...) 写日志，在「调试后台」页（需开"启用后端日志"）看；也可用 host.ShowToast 直接确认回调有没有进来
编译出来的插件中文乱码 源文件存成了 GBK（或带 BOM） 存成 UTF-8 无 BOM、CRLF
游戏或界面卡顿 在 ChatLineReceived / StatusText 里干了耗时活（联网、抓屏、等锁） 搬去 Task.Run，结果回到 UI 线程再更新界面
改了代码但行为没变 没重新编译，或编译了没重新导入 zip；宿主只在启动时扫描插件 重新 build-plugins.bat（或重新导入），必要时用「重新扫描」

11. 附录：给 AI 的速查规范

这一节是纯文本规范，方便直接喂给 AI 或复制粘贴。契约以 Plugins\Abstractions\PluginApi.cs 为准。

【契约】命名空间 MinecraftChatOverlay.Plugin，程序集 MinecraftChatOverlay.Plugin.Abstractions（net8.0-windows，不引 WPF）
【版本】PluginApi.Version = 1；plugin.json.apiVersion 必须 == 1
【入口】public sealed class XxxPlugin : IPlugin { string Id; string DisplayName; void Initialize(IPluginHost); void Shutdown(); }
        要求：public、非抽象、有公开无参构造；一个 dll 只放一个实现
【宿主能力 IPluginHost】ApiVersion / PluginDirectory / PluginsRootDirectory / RegisterPage(PluginPage) / Log(string)
        / SendToOverlay(string) / ReassertOverlayTopmost() / ShowToast(string)
        / event Action<ChatLine>? ChatLineReceived / IReadOnlyList<ChatLine> RecentChatLines
        / IReadOnlyList<GameWindowInfo> GetGameWindows()
【数据】ChatLine(string Raw, DateTime Time)；GameWindowInfo(IntPtr Handle, int ProcessId, string ProcessName, string Title, int Width, int Height)
        PluginOption(string Key, string Text)
【页面 PluginPage】required string Title; string? Description; List<PluginField> Fields; List<PluginAction> Actions;
        Func<string>? StatusText;   // 为 null 时宿主不画状态行
        Func<object>? ContentFactory;  // 返回 WPF FrameworkElement = 自绘；设了它就不渲染 Fields/Actions
【字段 PluginField】required string Key; string Label; PluginFieldKind Kind; string? Hint;
        Toggle: bool Bool | Slider: double Number, Minimum, Maximum, Step, string Suffix, string NumberFormat
        Text/ReadOnly: string Text | Select: string? SelectedKey, Func<IReadOnlyList<PluginOption>>? OptionsProvider, double OptionsRefreshSeconds
        Action<PluginField>? Changed; bool Enabled
【按钮 PluginAction】required string Label; bool Primary; Func<string?>? Invoke; bool Enabled
【存配置】PluginSettingsFile.Load<T>(dir, "settings.json")；PluginSettingsFile.Save(dir, value, "settings.json")
【硬规则】
 1) 只引用契约程序集，绝不引用主程序 exe
 2) TargetFramework = net8.0-windows；要界面才开 UseWPF；要 SendKeys 才开 UseWindowsForms
 3) 自绘页面里样式/画刷必须 DynamicResource（StaticResource 会 XamlParseException）
 4) 页面"值变即保存"必须加 _loading 闸门，否则填值时会把空值写回设置
 5) Shutdown() 里退订事件、关窗口/定时器（宿主会调，不清理会漏）
 6) 所有回调都在宿主 UI 线程：不要阻塞，耗时操作 Task.Run
 7) 用户数据只写 host.PluginDirectory（更新插件不会动它）；不要写插件安装目录
 8) 不写 StatusText 就不显示状态行；ReadOnly 字段也能展示状态
 9) 一个插件只注册一个页面（重复调用以最后一次为准）
10) 插件包 zip 只放 dll + plugin.json（+依赖 dll/资源）；不要放 bin/obj/pdb/契约 dll
【安装位置】%AppData%\MinecraftChatOverlay\plugins\<id>\ ；数据 %AppData%\MinecraftChatOverlay\plugin-data\<id>\
【文档配套】仓库自带 build-plugins.bat（编译+装机+打 zip 到 plugin-packages\）
