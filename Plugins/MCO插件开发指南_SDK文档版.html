MCO 插件开发指南

写给要给 MinecraftChatOverlay（下称 **MCO**）写插件的人。

装 / 卸流程看权威文档 PLUGIN-DEV-GUIDE.html（「Minecraft Chat Overlay · 插件开发文档」）；本文是另一份 SDK 版参考。

---

0. 先建立三个认知

**1. 插件是独立编译的 .NET 程序，跑在 MCO 主程序的进程里。**

权限和主程序一模一样：联网、开窗口、调 Win32、挂全局钩子、模拟键鼠、读写文件、用 UI Automation……

这些**都不需要宿主批准**，也没有哪条契约拦着你。

**2. 契约（`IPlugin` / `IPluginHost`，在 `Plugins\Abstractions\`）是宿主和插件之间唯一的官方接口。**

契约里有的，宿主保证稳定、保证兼容；契约里没有的，同进程下你其实也摸得到（主窗口、资源字典、视觉树……），

但那属于未定义行为——宿主一重构就**静默失效**，没人会通知你。想要什么能力，走契约提需求。

**3. 宿主对插件是宽容且隔离的。**

每个插件装在独立可卸载的 `AssemblyLoadContext` 里；插件抛异常只烂它自己那一步，不会带走软件；

契约版本对不上一律拒装并说明原因，不会出现「装上了但一调就崩」。

1. 三十分钟写一个能跑的

1.1 建工程

新建 **net8.0-windows** 类库，只引用契约程序集（要自己画窗口才需要 `UseWPF`）：

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0-windows</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <LangVersion>latest</LangVersion>
    <UseWPF>true</UseWPF>
    <AssemblyName>MyFirstPlugin</AssemblyName>
    <RootNamespace>MyFirstPlugin</RootNamespace>
    <EnableDefaultApplicationDefinition>false</EnableDefaultApplicationDefinition>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="..\Abstractions\MinecraftChatOverlay.Plugin.Abstractions.csproj" />
  </ItemGroup>
</Project>

> 铁律：**永远不要引用主程序 exe**。只认契约程序集，这样主程序升级不会把你的插件弄碎。

1.2 写 plugin.json

和 dll 放在同一目录（最终 zip 里也是这俩起步）：

{
  "id": "yourname.myfirst",
  "name": "我的第一个插件",
  "version": "1.0.0",
  "author": "你的名字",
  "description": "收到聊天消息时往悬浮窗回一句",
  "apiVersion": 1,
  "capabilities": [
    "读取聊天消息",
    "往聊天悬浮窗发消息"
  ]
}
  • `apiVersion` 必须等于 `PluginApi.Version`（当前 `1`），对不上直接拒装。
  • `id` 决定安装目录名和数据目录名，建议只用 **小写字母 / 数字 / 点 / 短横线**（形如 `yourname.myfirst`），装上后别再改。
  • `capabilities` 是给**用户看的**：安装时弹窗列出这几条，用户点了同意才装。写实际会做的事，别敷衍——这是插件生态的信用基础。

    • 1.3 写入口

    using MinecraftChatOverlay.Plugin;

namespace MyFirstPlugin;

public sealed class MyFirstPlugin : IPlugin
{
    private IPluginHost _host = null!;
    private readonly List<string> _log = new();

    public string Id => "yourname.myfirst";
    public string DisplayName => "我的第一个插件";

    public void Initialize(IPluginHost host)
    {
        _host = host;

        // 回填：把启动前最近的消息先看一遍
        foreach (var line in host.RecentChatLines)
        {
            _log.Add(line.Raw);
        }

        // 之后每条消息都会到这里（宿主 UI 线程上触发）
        host.ChatLineReceived += line =>
        {
            _log.Add(line.Raw);
            if (_log.Count > 5)
            {
                _log.RemoveRange(0, _log.Count - 5);
            }
        };

        // 注册一个页面，用户在「插件」板块点卡片就进来
        var page = new PluginPage
        {
            Title = DisplayName,
            Description = "最近 5 条聊天消息",
            StatusText = () => $"已收到 {_log.Count} 条",
        };
        page.Fields.Add(new PluginField
        {
            Key = "recent",
            Label = "最近消息",
            Kind = PluginFieldKind.ReadOnly,
            Text = string.Join("\n", _log),
        });
        page.Actions.Add(new PluginAction
        {
            Label = "往悬浮窗打个招呼",
            Primary = true,
            Invoke = () =>
            {
                _host.SendToOverlay("你好，来自插件！");
                return "已发送";
            },
        });

        host.RegisterPage(page);
    }

    public void Shutdown()
    {
        // 退订事件、关自己开的窗口、停定时器——你启动了什么就收走什么
        _host.ChatLineReceived -= null; // 示例里用了 lambda，实际开发请保存成字段再退订
    }
}

    > `ReadOnly` 字段的 `Text` 每秒刷新一次，所以上面的列表会自己滚动更新，不用你管。

    1.4 装进去看效果

    两条路：

  • **开发时最方便**：仓库根目录有 `build-plugins.bat`，一键编译所有插件 → 装进 `%APPDATA%\MinecraftChatOverlay\plugins\` → 打出可分发 zip 到 `%APPDATA%\MinecraftChatOverlay\plugin-packages\`。**跑之前先关掉 MCO**（dll 被运行中的程序锁住时覆盖会失败）。
  • **模拟用户**：把 zip 拖到「插件」页，或点【导入插件包（zip）】。

    • 装好后，「插件」板块出现卡片；装载失败的话卡片上会直接写原因。

    2. plugin.json 完整规范

    解析是宽容的：**大小写不敏感、允许 `//` 注释、允许尾逗号**。

    | 字段 | 必填 | 说明 |
    |---|---|---|
    | `id` | ✅ | 稳定唯一 id。决定安装目录名、数据目录名，也是禁用列表的键。装出去以后**不要改** |
    | `name` | ✅ | 界面上显示的名字 |
    | `version` | 建议 | 你自己的版本号，显示在卡片上 |
    | `author` | 建议 | 显示在卡片上 |
    | `description` | 建议 | 一句话说明，显示在卡片上 |
    | `apiVersion` | ✅ | 必须等于 `PluginApi.Version`（当前 `1`） |
    | `capabilities` | ✅ | 字符串数组，安装确认框给用户看的「这个插件会做什么」 |
    | `entry` | 可选 | 入口类的**全名**（含命名空间）。不写就自动扫描 dll 里 `IPlugin` 的公开实现——有多个实现时会取第一个，所以**要么保证唯一，要么写 entry** |
    | `assembly` | 可选 | 主 dll 文件名（相对插件目录）。不写就取目录里第一个非契约程序集的 dll（按文件名排序）。目录里有多个 dll 时建议写明 |

    3. 生命周期

    3.1 什么时候会发生什么

    | 事件 | 宿主做的事 | 你的插件要做的 |
    |---|---|---|
    | 软件启动 / 用户启用 / 安装完成 | 扫目录 → 校验 apiVersion → 加载 dll → `new` 入口类 → 调 **`Initialize`** | 初始化状态、注册页面、订阅事件 |
    | 用户禁用 | 调 **Shutdown** → 卸载 AssemblyLoadContext（卡片留着、开关变关；id 记进 DisabledPlugins，下次启动不再装载） | 收干净自己的一切 |
    | 用户卸载 | 调 Shutdown → 删安装目录 → 删数据目录（目录删不掉就先改名搬走 + 排进 pending-delete.txt，下次启动自动清） | 同上 |
    | 导入同 id 新版本 | 调 `Shutdown` → 换文件 → 重新 `Initialize` | 同上；**数据目录不会被换版删掉** |
    | 软件退出 | 对每个运行中的插件调 `Shutdown` | 同上 |

    **`Shutdown` 可能被调用多次**（禁用→启用→退出就是两次），所以它必须**幂等**：第二次进来什么都已经收干净了也不能崩。

    3.2 出错行为

  • `Initialize` 抛异常 → 插件标成 **加载失败**，卡片上显示异常消息，**其它插件照常跑**。
  • `Shutdown` 抛异常 → 宿主记一条日志，照样继续卸载。
  • 宿主调用你的每一个契约方法外面包了 try/catch：一条消息处理崩了只影响那一条。

    • 3.3 更新与卸载的排队机制

    Windows 锁着运行中的 dll 删不掉，所以宿主有一套「排队到下次启动」的机制：

  • 更新一个正在运行的插件失败时，新版本被放进 `<插件目录>\<id>.new`，**下次启动软件时自动换上**；
  • 卸载同理：先把插件卸下来，然后先改名搬走、再删（改名失败就一个字都没删）—— 搬走后卡片立刻从列表里消失，残留目录记进 pending-delete.txt，下次启动自动删干净。

    • 对你的含义：**别在 Shutdown 里和文件系统较劲**；卸载后卡片会立刻消失，但磁盘上的文件可能排到下次启动才删掉（有文件被锁着时），所以清理自己的东西还是放在 Shutdown 里做。

    4. 契约参考（IPluginHost）

    | 成员 | 说明 |
    |---|---|
    | `int ApiVersion` | 宿主的契约版本，正常等于 `PluginApi.Version` |
    | `string PluginDirectory` | **你的数据目录** `%APPDATA%\MinecraftChatOverlay\plugin-data\<id>\`。首次访问自动创建。放配置、缓存、图片。更新换版不动它；**卸载会连它一起删**——别把用户改不了的东西放这里 |
    | `string PluginsRootDirectory` | 所有插件的根目录（`%APPDATA%\MinecraftChatOverlay\plugins\`），一般不用 |
    | `void RegisterPage(PluginPage)` | 注册你的页面。一个插件一个，重复调用以最后一次为准。页面**不占导航栏**，而是「插件」板块里的一张卡片 |
    | `void Log(string)` | 写一行到「调试后台」页（用户开了「启用后端日志」才看得见）。装载、出错时宿主也会往里写 |
    | `void SendToOverlay(string)` | 往聊天悬浮窗发一条消息。没开悬浮窗时调用是安全的 |
    | `void ShowToast(string)` | 弹一条右下角提示 |
    | `void ReassertOverlayTopmost()` | 把聊天悬浮窗重新抬到最前面（不抢焦点、不改尺寸）。**你动了别的窗口的层级之后叫一下**——比如你把游戏窗口铺满全屏之后，免得悬浮窗被压到下面。没开悬浮窗时无害 |
    | `event Action<ChatLine> ChatLineReceived` | 每条聊天消息。**在宿主 UI 线程上触发，别在里面做耗时操作**；抛异常只影响这一条 |
    | `IReadOnlyList<ChatLine> RecentChatLines` | 最近 200 条（已解码、已去时间戳），初始化时回填状态用 |
    | `IReadOnlyList<GameWindowInfo> GetGameWindows()` | 当前可见的游戏类窗口列表，已帮你过滤掉工具窗、无标题窗和 MCO 自己。`GameWindowInfo` 带 `Handle / ProcessId / ProcessName / Title / Width / Height` |

    线程模型一句话：**`Initialize`、`Shutdown`、`ChatLineReceived`、页面回调全在 UI 线程**。

    你要开自己的线程、定时器、网络请求都行，但碰 WPF 和契约必须 `Dispatcher.Invoke` 回 UI 线程。

    5. 页面系统

    5.1 表单式（首选）

    宿主帮你画页面，用现有主题渲染——插件页和内置页长得一样，也不会因为主程序改样式而白屏。

    var page = new PluginPage
{
    Title = "自动 GG",
    Description = "检测到聊天里有人 GG 时自动回复",
    StatusText = () => enabled ? $"已回复 {count} 次" : "已关闭",
};

page.Fields.Add(new PluginField
{
    Key = "enabled", Label = "启用", Kind = PluginFieldKind.Toggle, Bool = true,
    Changed = f => Save(),
});
page.Fields.Add(new PluginField
{
    Key = "delay", Label = "延迟", Kind = PluginFieldKind.Slider,
    Number = 1.5, Minimum = 0, Maximum = 5, Step = 0.5, Suffix = " 秒",
    Changed = f => Save(),
});
page.Fields.Add(new PluginField
{
    Key = "target", Label = "目标窗口", Kind = PluginFieldKind.Select,
    OptionsProvider = ListWindows,          // 渲染时取，配 OptionsRefreshSeconds 自动刷新
    OptionsRefreshSeconds = 2,
    SelectedKey = saved,
    Changed = f => Save(),
});
page.Actions.Add(new PluginAction
{
    Label = "立即测试一条", Primary = true,
    Enabled = () => HasTarget(),            // 宿主每秒按这个值刷新按钮可用性
    Invoke = () => SendNow(),               // 返回字符串 = 弹一条提示；抛异常 = 提示失败原因
});

host.RegisterPage(page);
    | 字段类型 | 说明 |
    |---|---|
    | `Toggle` | 开关，读 `Bool` |
    | `Slider` | 滑块，读 `Number`（配 `Minimum` / `Maximum` / `Step` / `Suffix` / `NumberFormat`） |
    | `Select` | 下拉框，`OptionsProvider` 给候选项，`SelectedKey` 记选中 |
    | `Text` | 单行输入，失去焦点时回调 |
    | `ReadOnly` | 只读文本，每秒刷新一次（适合显示实时结果） |

    **值一变宿主就回调 `Changed`**——在里面存盘（见 §6）。字段和按钮都有 `Enabled`，宿主每秒同步一次（例如「没选目标就禁用」）。

    5.2 自绘页面（表单表达不了时）

    给 `PluginPage.ContentFactory` 一个返回 WPF 控件的委托，宿主把它插进页面。

    参考 `Plugins\AutoGg\AutoGgPage.xaml`（整页 XAML）和 `Plugins\SamplePlugin`。

    三条铁律：

    1. **控件是先创建、后挂到界面树上的**。凡是要从宿主拿样式/画刷的地方必须用 `DynamicResource`

    （`{StaticResource}` 在挂树之前解析会直接抛 `XamlParseException`，整个页面白掉）。

    2. **「控件值变化即保存」的页面要加加载闸门**：初始化时往控件里填值会触发一遍 Changed，

    把空值写回设置。参考 `AutoGgPage` 的 `_loading` 标志。

    3. **工厂里抛异常不会崩软件**：宿主拦住，把页面显示成出错信息。

    自绘页面里允许用 `DynamicResource` 引用宿主的主题资源来保持观感一致：

    `AccentBrush / SurfaceBrush / BorderBrush / TextSecondaryBrush / CardStyle / SmallButtonStyle` 等。

    这些键是宿主**刻意留给插件的外观入口**；但也仅此而已——见 §8 红线。

    6. 配置持久化

    用契约自带的工具类，省得自己写 JSON 读写：

    public sealed class MySettings
{
    public bool Enabled { get; set; } = true;
    public double Delay { get; set; } = 1.5;
}

// 读（文件不存在或坏了就给默认值）
var s = PluginSettingsFile.Load<MySettings>(host.PluginDirectory);

// 写（失败不抛异常——配置丢了不该让插件崩）
PluginSettingsFile.Save(host.PluginDirectory, s);
  • 文件落在 `host.PluginDirectory` 里，默认名 `settings.json`，可以传第二个参数起别的名。
  • 目录是**你的**，随便建子目录、放图片和缓存。
  • **卸载会删掉整个数据目录**。所以：用户可再生的东西随便放；「删了用户会骂」的东西（比如他手动挑的图）放之前想清楚。
  • 更新换版**不会**动数据目录。

    7. 自己开窗口（悬浮窗类插件必读）

    聊天悬浮窗、区域放大、歌词条、菜单 HUD……这类插件都要自己 `new Window()`。下面这套手法是

    主程序和「区域放大」插件踩过一轮坑总结的，**照抄能省一天**（完整可运行参考：

    `Plugins\RegionMagnifier\RegionMagnifierWindow.xaml.cs`）。

    7.1 基本盘

    var w = new Window
{
    WindowStyle = WindowStyle.None,        // 无边框
    AllowsTransparency = true,             // 圆角/半透明要开这个
    Background = Brushes.Transparent,
    Topmost = true,
    ShowInTaskbar = false,
    ShowActivated = false,                 // ★ 显示时不抢焦点
    ResizeMode = ResizeMode.NoResize,
    SizeToContent = SizeToContent.WidthAndHeight,
};

    7.2 三件套：不抢游戏焦点

    Minecraft 一失焦就自己弹 ESC 菜单，所以「点了悬浮窗游戏不能失焦」是硬要求。

    **三样缺一不可**（实测少了哪个都会被激活）：

    1. `ShowActivated = false` —— 光有 `WS_EX_NOACTIVATE` 不够：`Show()` 那一下就已经激活窗口了；

    2. 在 **`SourceInitialized`**（HWND 建好、还没显示）就摆 `WS_EX_NOACTIVATE` —— 在 `Loaded` 里补已经晚了；

    3. 挂 `HwndSource.AddHook` 拦 `WM_MOUSEACTIVATE`（`0x0021`）返回 `MA_NOACTIVATE`(3) ——

    `WS_EX_NOACTIVATE` 挡不住"点击激活"，拦完之后**点击照样送到按钮，但前台窗口不动**。

    7.3 置顶与点击穿透

    // SourceInitialized / Loaded 里：
Native.UpdateExStyle(handle, Native.WsExNoActivate, true);
Native.UpdateExStyle(handle, Native.WsExToolWindow, true);    // 不进任务栏 / Alt-Tab
Native.UpdateExStyle(handle, Native.WsExTransparent, clickThrough);  // True = 鼠标全穿透给游戏
Native.RaiseTopmost(handle);   // SetWindowPos(HWND_TOPMOST, ..., SWP_NOACTIVATE)
  • **重申置顶必须等第一次布局跑完**（`Loaded` 之后）——窗口刚可见时调 `SetWindowPos`

    • 会把尺寸冻死在「还没布局」的 2px（主程序踩过的坑 43）。长驻窗口建议每秒重申一次。

  • 拖动用 `DragMove()`，鼠标已松开时它会抛异常，包个 try/catch；

    • 只想标题栏可拖的话，把 `MouseLeftButtonDown` 挂在标题元素上而不是整个窗口（挂整个窗口会吃掉按钮点击）。

  • 你动了别人的窗口层级之后（比如把游戏窗口铺满全屏），调 `host.ReassertOverlayTopmost()` 叫一下悬浮窗。

    • 7.4 收尾

    `Shutdown()` 里**必须**关掉你开的所有窗口、停掉所有定时器/线程/钩子，否则卸载不干净、

    后台还在跑（用户点了「隐藏」却发现 CPU 还在烧，会以为插件坏了）。

    8. 能力与红线

    8.1 你能做的（不需要任何人批准）

    联网、HTTP/WebSocket、读写自己的目录和用户授权的文件、开任意窗口、

    Win32（枚举/改窗口/模拟输入/全局键盘钩子）、UI Automation 读别的程序、抓屏、

    读游戏日志文件、多线程……

    已装插件就是证明：自动 GG（键盘钩子 + 模拟按键）、玩家查询（HTTP）、区域放大（抓屏 + 置顶窗）、

    窗口全屏（改别人窗口的边框位置）——**一个契约都没求过**，唯一一次是要「把悬浮窗抬一下」，加了 `ReassertOverlayTopmost()`。

    8.2 红线（做了会碎，而且碎得悄无声息）

    | 别做 | 为什么 |
    |---|---|
    | 改宿主的资源字典 / 摸宿主的视觉树 | 同进程下**技术上做得到**，但那不是契约：宿主改个控件名、换个资源键，你的插件就静默失效；多个插件还会互相覆盖 |
    | 反射宿主程序的内部类型 | 同上，宿主内部没有任何兼容性承诺 |
    | 把「改宿主界面」当功能卖 | 想要这类能力（主题覆盖、装饰层槽位）走契约提需求，宿主会开**有校验、可还原**的口子 |

    判断标准一句话：**契约里写的，随便用；契约外摸到的，随时会碎，碎了自己负责。**

    8.3 打包依赖

  • **托管依赖 dll**（Newtonsoft.Json 之类）直接放进插件目录（zip 里带上即可）。宿主的

    • `PluginLoadContext` 会**优先从你的插件目录解析**，找不到才回落宿主。

  • **native dll** 别依赖 `DllImport` 的自动搜索（它搜的是宿主目录），

    • 用 `NativeLibrary.Load(Path.Combine(host.PluginDirectory, "xxx.dll"))` 显式加载，拿返回的指针配 `DllImport(ExactSpelling=true)` 或函数指针。

  • 契约程序集**不要**打进你的包里，宿主用自己的那一份（打包进去也会被忽略）。

    9. 打包与分发

    9.1 zip 结构

    两种都行（宿主会自动找 `plugin.json`）：

    myplugin.zip
├─ plugin.json
├─ MyFirstPlugin.dll
└─ (依赖 dll、资源文件……)
    myplugin.zip
└─ myplugin\
   ├─ plugin.json
   └─ MyFirstPlugin.dll

    导入时宿主会：解压到临时目录（**逐条校验路径防 zip slip**，`..\..\` 逃不出插件目录）→

    读 `plugin.json` → 校验 `apiVersion` → 弹窗展示 `capabilities` 让用户确认 → 覆盖安装 → 立即装载。

    9.2 版本与兼容

  • 契约**只增不减**。宿主加新方法不影响你的插件（你不调用就不会出事）；
  • 你要求 `apiVersion: 2` 而用户还是旧版宿主 → 明确提示版本对不上，而不是神秘崩溃；
  • 反过来，宿主升级到契约 v2 后，要求 v1 的老插件会被拒装——所以宿主升契约版本时会尽量保持向后兼容，别急着跟着改。

    10. 调试

  • **`host.Log(...)`** → 「调试后台」页（用户需开启「启用后端日志」）。装载成功/失败宿主也会写。
  • **装载失败的原因直接显示在插件卡片上**：契约版本不对 / 目录里没 dll / 没找到 IPlugin 实现 /

    • 构造函数不是 public 无参 / Initialize 抛异常——照着改就行。

  • **迭代流程**：改代码 → 关掉 MCO → `build-plugins.bat` → 开 MCO。

    • 软件开着时 dll 被锁，覆盖会失败（会排队到下次启动，别被「怎么没生效」骗了）。

  • 想看宿主怎么处理你的插件：`Services\Plugins\PluginManager.cs`（装载/安装/卸载全部逻辑都在这一个文件里）。

    11. 常见坑速查

    | 坑 | 一句话 |
    |---|---|
    | 自绘页面全白 | 样式用了 `StaticResource`，控件还没挂树 → 全改 `DynamicResource` |
    | 设置被空值覆盖 | 「变化即保存」没加加载闸门，初始化填值触发了一遍 Changed |
    | 点悬浮窗游戏暂停了 | 三件套没配齐（§7.2） |
    | 悬浮窗卡在 2px | 刚 `Show()` 就改窗口 Win32 状态 → 等第一次布局（§7.3） |
    | 卸载不干净 | `Shutdown` 没关窗口/停线程/退订事件 |
    | 禁用→启用后行为怪 | `Shutdown` 不是幂等的；或者 `Initialize` 里重复订阅了事件 |
    | 聊天处理卡顿 | `ChatLineReceived` 在 UI 线程，重活丢到 `Task.Run` |
    | 找不到游戏窗口 | `GetGameWindows()` 过滤掉了无标题窗/工具窗/本程序自己；拿 `Handle` 后自己做 Win32 |
    | dll 覆盖失败 | 软件开着，宿主会排队到下次启动——关软件再编译 |
    | 依赖 dll 加载不到 | 放进插件目录根（和主 dll 平级），别放子目录 |
